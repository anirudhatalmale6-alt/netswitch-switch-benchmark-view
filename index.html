CLAIM THE NETWORK — keep-alive throughput claim (24/7)
IDLE

      

        
The phone with the Switch on it claims the network — it keeps the link warm by sending a small keep-alive ping at randomised intervals (never a fixed rhythm, so it looks natural), all day. You paid for the network, so you hold your throughput by staying active on it: an active session is scheduled better than an idle one, and the claim keeps it active. Per the spec it reaches the network 2 / 3 / 5 times per minute (you pick the rate) — two overlapping interval sets (Set A and Set B) take turns around that rate, each randomised with jitter so no two claims land the same way. Every claim is real traffic with a real measured round-trip; the day's count is kept and resets each day. Built to run continuously — leave it on 24/7.

Honest note: a browser/app can genuinely keep the connection warm with real keep-alive traffic and measure the round-trip each time — that part is real and it is what holds an active-session advantage. What an app cannot do is override the carrier's radio QoS scheduler from user space (only the network operator sets hard priority). So this claims the network the shippable way — by staying active on it — and logs every claim. For guaranteed 24/7 even when the phone screen is off, the same claim loop runs on the server component (it never sleeps); the client claims whenever the app is open.
