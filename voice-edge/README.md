# 6GGW / NetSwitch — voice slice (`ggw_voice_edge`)

A real, runnable slice of the voice-rerouting picture: a thin client registers
to an edge with a **one-time backup code**, places a **SIP call**, and streams
**real RTP voice** (G.711 µ-law) that the **media edge relays back** — proving
the whole path end to end. No Kamailio / rtpengine install needed to see it
work; the wire format is the same, so this scales straight onto them.

## What actually happens (all real protocol, not a mock)

1. **REGISTER (gated)** — client sends SIP REGISTER with `X-Backup-Code: …`.
   The edge verifies it against the backup-codes list and **burns it** (salted
   SHA-256, same as `backup-codes/` and `registrar/`). Bad or used code → `403`.
2. **INVITE / 200 / ACK** — client calls; the edge allocates an **RTP port** and
   returns it in SDP (`m=audio <port> RTP/AVP 0`, PCMU/8000). This is the media
   edge picking where the voice flows.
3. **RTP media** — client streams 25 real RTP packets (RFC 3550 header + a 440 Hz
   sine tone encoded as **G.711 µ-law**, 20 ms/160 samples each — 0.5 s of
   actual voice-shaped audio). The edge **relays every packet back**; the client
   checks each one arrived intact.
4. **BYE / 200** — call torn down; the edge reports how many packets it relayed.

## Run it

```
# one-process demo (edge + client together) — the quickest way to see it:
ggw_voice_edge selftest --config codes.switchc.xml --code WYQM7-XJ8JT

# or two processes / two machines:
ggw_voice_edge serve --sip-port 45060 --config codes.switchc.xml     # the edge
ggw_voice_edge call  --host 127.0.0.1 --sip-port 45060 --code WYQM7-XJ8JT
```

(`codes.switchc.xml` is generated by `backup-codes/ggw_backupcodes gen`.)

Verified output:

```
[edge] REGISTER from 127.0.0.1 -> 200 OK (code #1)
[edge] INVITE ... -> 200 OK, media edge port 32868
[client] media: sent 25 PCMU packets (0.5s of 440Hz tone), 25 relayed back intact
[edge] BYE — relayed 25 media packets this call. Tearing down.

PASS  register=ok  call=ok  media=25/25 round-tripped through the edge
```

Security is the gate — tested and passing:

| code | result |
|------|--------|
| valid, unused | REGISTER 200 → call → 25/25 media relayed → **PASS** |
| wrong code | REGISTER **403**, no call, no media |
| a code already used | REGISTER **403** (one-time burn holds across the SIP path) |

Verified on Linux (native) and Windows (`.exe`, winsock, under wine).

## How this maps to the production edge

This binary plays both the thin client and a minimal edge so it runs anywhere.
In production the pieces are the proven ones, same wire format:

```
  thin client (phone)  ──SIP REGISTER/INVITE──▶  Kamailio  ──picks edge via──▶  6GGW rerouting engine
        │                                            │                              (RTT least-cost POP)
        └──────────── RTP (PCMU) ───────────────────▶  rtpengine at that edge  ◀────────┘
                                                     (RTP handler / scaler = the media edge)
```

- the **REGISTER gate** here is what a real Kamailio auth module enforces;
- the **RTP relay** here is what **rtpengine** does at carrier scale;
- the **edge selection** is already handled by the NetSwitch rerouting engine.

So the demo isn't throwaway: the client speaks real SIP+RTP, so pointing it at a
real Kamailio+rtpengine edge is a config change, not a rewrite.

## Build

```
# Linux
g++ -std=c++17 -O2 -pthread ggw_voice_edge.cpp -o ggw_voice_edge

# Windows (mingw; MSVC works too)
x86_64-w64-mingw32-g++ -std=c++17 -O2 ggw_voice_edge.cpp -o ggw_voice_edge.exe -static -lws2_32
```
