Technical specification · the on-device measurement suite

A set of pages that measure the real hardware of the phone or computer they are opened on — the processors, the memory, the graphics and the screen — and report each figure with how far it can be trusted. Everything runs in the device's own browser. Nothing is sent anywhere.

How every figure is marked

No number is presented as plain fact. Each one carries how it was obtained, so a reader always knows whether it was timed on the device or merely reported by it:

MEASURED timed on this device, here, now
READ stated by the device, taken as given
NOT POSSIBLE cannot be had from a browser, and the page says so rather than guessing

This device, measured as the page loaded

These are live readings from the device this page is open on, to show the suite working. Any handset will differ from a figure printed in a brochure, which is the whole point.

How the measuring is done honestly

  • Memory access time is taken so that each read waits on the one before it, so the processor cannot run ahead and the figure is a true access time rather than a throughput.
  • Every timing is taken more than once and the quickest kept, because interference on a busy machine can only ever make a reading come out slow, never fast.
  • The levels of memory are found from the shape of the readings, not assumed. A device with two levels reports two; a device with five reports five.
  • Each processor is measured on its own, so the figure is every processor reporting rather than a count standing in for them.
  • A reading that moves — the access time, the processor rate — is never used as a secret key, because a key must come out identical every time and a measurement never does.

What it will not claim

The honest limits are part of the specification, because a product that oversells is taken apart by the first buyer who checks:

NOT POSSIBLE A browser cannot read the SIM card, the operator or the telephone number. Reading those needs an installed app with permission, not a page.
NOT POSSIBLE The whole machine's load, and the processor type and clock, are not visible from a browser. They need the operating system.
NOT POSSIBLE A phone on a mobile network has no public address of its own and cannot be reached from outside as a server without a tunnel.

How it is delivered

  • It runs from the device's own storage with no network and no certificate, and loses nothing that way — a browser trusts a file on its own disc.
  • Served to the phone from the phone itself, over a plain local connection, it also keeps every reading. A certificate is only needed when the pages are served to a different machine across a network.
  • A broken certificate is worse than none: the browser stops the page before it runs. That case is handled and documented rather than left to surprise a user.

How it is checked

Each part carries its own test, which stays silent while it passes and speaks up only when a figure stops holding together — so a page that looks right has also been shown to be able to catch itself being wrong. The tests check the failures, not just the successes: a lock that opens for the right secret proves nothing until it is shown to refuse the wrong one.

Everything described as measured was timed on real devices. Figures shown here are from the device this page is open on and from reference handsets, never invented to fill a gap.
